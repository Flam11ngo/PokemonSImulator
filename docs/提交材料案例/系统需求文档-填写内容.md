# PokemonSimulator 系统需求文档

---

## 1. 项目概述

### 1.1 系统目标

本系统旨在构建一个集实时宝可梦对战与大数据埋点分析于一体的全栈 Web 平台。通过对战引擎提供 VS Bot 和 PvP 两种模式的回合制对战体验，同时基于 Kafka + ADS Bridge + SQLite 构建从数据采集、管道传输到聚合可视化的完整大数据链路，最终以实时看板、Smogon 排名分析和用户行为分析三个维度呈现数据价值。

预期读者：项目开发团队、答辩评审老师、系统运维人员。

### 1.2 职责与范围

#### 1.2.1 功能范围

系统包含以下核心功能模块：

- **宝可梦对战系统**：支持VS Bot人机对战和PvP玩家匹配对战，基于Pokemon Showdown引擎进行回合制战斗模拟，含HP条、伤害数字、濒死、换人等动画效果
- **精灵组队工具**：支持手动配招与Smogon大数据一键构建（自动推荐技能/道具/特性/努力值配置）
- **实时数据看板**：展示对战数量、精灵使用率排行、技能/道具/特性使用率统计，每30秒轮询刷新
- **Smogon数据分析面板**：支持source（smogon/模拟器）/时间/分级三维筛选，精灵排名、详细配招、月度趋势、天敌克制
- **用户行为分析**：页面浏览量、按钮点击量、玩家活跃度、事件流实时展示
- **模拟数据生成器（Data Daemon）**：8个Battle Worker + 3个UI Worker持续向Kafka推送模拟数据，队伍使用Smogon加权随机生成
- **前端埋点系统**：双通道采集（HTTP POST + WebSocket），覆盖页面浏览、点击、对战全生命周期事件

#### 1.2.2 技术范围

前端：Vue 3 + Vite + Chart.js + Axios + WebSocket

后端：Python FastAPI（API网关 + WebSocket对战服务 + 埋点接收 + Stats/Smogon代理）

对战引擎：Node.js子进程封装Pokemon Showdown引擎，stdin/stdout JSON-RPC通信

数据管道：Kafka消息队列（battle.logs / player.ui.events两个Topic） → kafka_to_sqlite.py桥接 → SQLite聚合数据库

VM集群：3节点Ubuntu 22.04（myz主节点 + lzx/cyc从节点），部署Kafka 3.9.2 + Hadoop 3.4.3 + Spark 3.5.8

数据库：
- pokemon.db（游戏静态数据，83MB，1050精灵/902技能/308特性/524道具）
- pokemon_stats.db（ADS聚合数据，14张表：meta_species/moves/items/abilities/recent_events等）
- gen91v1_stats.sqlite（Smogon排名数据，335MB，8张表：mon/move/ability/item/spread/team/cc/tera）

**部署与运维**：Systemd服务管理 + Nginx反向代理 + 一键部署脚本（单MASTER_IP驱动）

#### 1.2.3 用户群体

| 角色 | 说明 | 涉及功能 |
|------|------|---------|
| 普通玩家 | 进行宝可梦对战和队伍配置 | 对战匹配、组队构建、Smogon一键构建 |
| 数据分析师 | 查看统计数据和分析报告 | 实时看板、Smogon分析面板、用户行为分析 |
| 系统运维人员 | 维护系统稳定运行 | 部署管理、数据清理、Kafka/桥进程监控 |

#### 1.2.4 系统边界

```
┌─────────────────────────────────────────────────────────────────────┐
│                          系统边界                                    │
│                                                                     │
│  ┌──────────────────────────┐     Kafka      ┌───────────────────┐  │
│  │ Windows开发机             │ ◄──────────► │ VM集群 (Ubuntu)    │  │
│  │                          │               │                   │  │
│  │ • Vue3 前端 (7个页面)     │  battle.logs  │ • Kafka Broker    │  │
│  │ • Python API网关 (:9000)  │  player.ui.   │ • ADS Bridge      │  │
│  │ • Showdown对战引擎        │    events     │ • Stats API :8080 │  │
│  │ • Data Daemon (模拟数据)  │               │ • HDFS (可选)     │  │
│  │ • Pokemon/Smogon SQLite   │               │ • Spark (可选)    │  │
│  └──────────────────────────┘               └───────────────────┘  │
│                                                                     │
│  外部依赖: Tailscale虚拟组网, SSH互信, Smogon开源数据                │
└─────────────────────────────────────────────────────────────────────┘
```

系统内部包含：前端展示层 → API网关层 → 业务逻辑层 → 数据管道层 → 数据存储层。

系统不包含：用户注册/登录系统（仅localStorage存储用户名），支付/商业化模块，移动端APP。

#### 1.2.5 非功能需求

- **性能**：API响应<500ms（ADS查询），<2s（Smogon查询），WebSocket对战回合<1s
- **可用性**：Bridge/Daemon崩溃后systemd自动重启，Kafka Consumer Group保证消息不丢失
- **可靠性**：全链路UTC时间戳统一，ADS写入WAL模式保证原子性
- **可维护性**：日志统一输出，systemctl一键启停，部署脚本单参数驱动
- **可扩展性**：Kafka/Spark/HDFS支持多节点水平扩展，前后端模块独立解耦

## 3. 系统功能需求

### 表1 系统功能需求表

| 编号 | 功能名称 | 功能描述 | 优先级 |
|------|---------|---------|--------|
| F-01 | VS Bot对战 | 玩家选择队伍后与AI Bot进行回合制对战，Bot队伍由Smogon加权随机生成，支持技能选择、宝可梦切换、对战动画 | 高 |
| F-02 | PvP匹配对战 | 两名玩家在匹配队列中配对后进行实时对战 | 中 |
| F-03 | Showdown对战引擎 | Node.js子进程封装Pokemon Showdown引擎，stdin/stdout JSON-RPC通信，支持gen9customgame格式 | 高 |
| F-04 | 对战动画渲染 | 基于Showdown协议行（\`\|move\|\`、\`\|-damage\|\`、\`\|switch\|\`、\`\|faint\|\`等20+种）的状态驱动动画引擎 | 高 |
| F-05 | 队伍构建器 | 手动搜索精灵、选择技能/道具/特性/努力值/性格，支持保存和加载队伍 | 高 |
| F-06 | Smogon一键构建 | 点击精灵后自动从Smogon数据推荐最佳4技能+道具+特性+努力值配置 | 高 |
| F-07 | 实时数据看板 | 精灵使用率/技能使用率/道具携带率/特性使用率排行榜，每30秒刷新，支持搜索和排序 | 高 |
| F-08 | Smogon排名分析 | 数据源切换（smogon/模拟器）、分级筛选(0/1500/1630/1760)、月份选择，精灵排名+详情弹窗 | 高 |
| F-09 | 精灵详情弹窗 | 单只精灵的完整数据：技能/道具/特性使用率、队友搭配、天敌克制、月度趋势图、努力值分布 | 中 |
| F-10 | 用户行为分析 | 事件流实时展示、页面浏览排行、按钮点击排行、玩家活跃统计 | 中 |
| F-11 | 前端埋点(ODS) | 页面浏览（router.afterEach）、导航点击（@click）、对战全生命周期（battle_init/turn_executed/damage/faint/switch/result） | 高 |
| F-12 | Data Daemon模拟数据源 | 8 Battle Worker + 3 UI Worker并发向Kafka发送模拟数据，Smogon加权随机队伍生成（100只精灵×Top10配置） | 高 |
| F-13 | Kafka消息队列 | battle.logs和player.ui.events两个Topic（各3分区），承载对战和用户行为全量数据 | 高 |
| F-14 | ADS Bridge聚合 | kafka_to_sqlite.py消费Kafka→聚合写入SQLite 14张表（meta_species/moves/items/abilities/event_counts/summary_stats/recent_events等），每10秒更新百分比+全局统计 | 高 |
| F-15 | Stats HTTP API | VM stats_server.py (:8080)提供全量snapshot + deep/* + ui/* 端点，查询ADS聚合表 | 高 |
| F-16 | API网关 | FastAPI统一路由：REST（对战/队伍/精灵查询）+ WebSocket对战 + 埋点接收转发 + Stats/Smogon代理 | 高 |
| F-17 | Smogon数据库集成 | 从VM定期同步gen91v1_stats.sqlite（335MB，8张表），支持filters/ranking/detail/summary/moves/items/trend等端点 | 中 |
| F-18 | 数据清理 | Kafka按时间戳截断（offsets_for_times→delete_records），Consumer Group重置，ADS数据库重建 | 中 |
| F-19 | 一键部署 | 单MASTER_IP环境变量驱动，自动安装系统依赖/Python/Node/Kafka/Bridge/Stats/Nginx/systemd | 中 |
| F-20 | 全链路UTC时间戳 | 前端（new Date().toISOString()）、Python（datetime.now(timezone.utc)）、Kafka消息统一UTC | 高 |
| F-21 | Vite代理路由 | /api/v1/stats→VM:8080、/api/v1/smogon→VM:8080、/api→localhost:9000、/ws→localhost:9000 | 中 |
